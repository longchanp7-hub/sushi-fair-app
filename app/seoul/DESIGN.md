# 設計・作業工程とインテリジェンス

## 0. 結論

設計はプロ品質で固め、実装はCodexを使わずに行う。旅行中の操作は「選ぶ・押す・チェックする」に限定する。AIは予定変更や自由回答をせず、困りごとを分類して、確認済みの案内を提示する。

## 1. 条件整理

**作業**

- 日程、予約時刻、移動先、買い物、帰国便を一つのデータにまとめる。
- 地図画像どうしの食い違いを整理する。
- 店舗名や住所が未確認のものは、推測で確定しない。

**インテリジェンス**

- 固定条件と変更可能な条件を分ける。
- 「眉アート10:00・約3時間」と「仁川16:05発」の衝突を検出する。
- 旅行者本人が操作中に判断を迫られないよう、旅行前に不足情報を見える化する。

**成果物**

- `trip-data.js`
- 未登録の便名・ターミナルを本人が入力する画面
- 予約票を優先する注意書き

## 2. 情報設計

**作業**

画面を次の5つに限定する。

1. 今日
2. 地図
3. 買い物
4. 困ったとき
5. 空港

**インテリジェンス**

- 使用頻度と緊急度で情報を並べる。
- 専門用語を出さず、ボタン名を動作そのものにする。
- 一つの画面で一つの目的に集中できるようにする。

**成果物**

- 下部の5ボタン
- 大きな文字と44px以上の押しやすい領域
- iPhoneの画面下部・上部の安全領域対応

## 3. 旅程表示

**作業**

- 1日ごとに予定を時系列で表示する。
- 終わった予定をチェックできるようにする。
- 次に未完了の予定を最上部に表示する。

**インテリジェンス**

- 予約時刻のある予定を「予約」として強調する。
- 予定は組み替えず、危険な時間関係だけ警告する。
- 旅行日より前、旅行中、旅行後で表示を切り替える。

**成果物**

- 3日分のタイムライン
- 完了状態をiPhone内に保存
- 3日目の赤い時間警告

## 4. 地図と移動

**作業**

- 弘大、明洞、聖水、汝矣島、市場、東大門、ソウル駅、仁川空港の位置関係を整理する。
- 各場所からAppleマップを直接開けるようにする。
- タクシーや店員に見せる韓国語表記を大きく表示する。

**インテリジェンス**

- イラスト地図を実際のナビに使わせず、位置関係の理解だけに使う。
- 店舗の正確な住所が未確認なら、地域または駅までに留める。
- 表示用の韓国語は旅行者に読ませず、「見せる」用途に限定する。

**成果物**

- 修正版の簡易地図
- Appleマップへの検索リンク
- 「画面を見せる」カード

## 5. 困ったとき

**作業**

- よくある困りごとを12種類に整理する。
- ボタン選択と、日本語の自由入力の両方を用意する。
- 電話・地図・該当画面へすぐ移動できるようにする。

**インテリジェンス**

- AIは文章の意味がどの困りごとに近いかだけを判定する。
- 回答文をAIに自由生成させず、事前確認した安全な案内を表示する。
- AIが読み込めなくても、単語による基本判定へ自動で戻す。
- 命や安全に関わる内容では、AIより電話を優先する。

**成果物**

- Hugging Face Transformers.jsをWeb Workerで実行
- 多言語文章モデルによる意味の近さの判定
- 112、119、1330、日本大使館の電話ボタン

## 6. 空港モード

**作業**

- 出発時刻から空港到着目標と弘大出発目標を逆算する。
- 便名とターミナルを保存できるようにする。
- 空港へ出る前の確認項目を用意する。

**インテリジェンス**

- 出発16:05の3時間前を空港到着目標とする。
- 弘大から空港まで80分の安全側の作業用目安を置く。
- 眉アートの予定と両立しないことを明確に表示する。
- 自動で予定を変更せず、本人が予約票を確認するよう促す。

**成果物**

- 空港到着目標13:05
- 弘大出発目標11:45
- 帰国便の登録画面
- 空港チェックリスト

## 7. 保存・オフライン

**作業**

- 完了チェック、買い物、便名などをiPhone内に保存する。
- 基本画面を電波が弱い場所でも開けるようにする。

**インテリジェンス**

- 個人情報を外部サーバーへ保存しない。
- モデルの大きな読み込みは本人の明示操作後だけ行う。
- 一度準備したAI部品はブラウザーの保存領域を利用する。

**成果物**

- localStorage
- Service Worker
- PWAマニフェスト

## 8. 品質確認

**作業**

- JavaScriptの文法確認
- iPhone相当の縦画面で表示確認
- 全5画面、チェック保存、ダイアログ、リンク、AI失敗時の代替動作を確認
- GitHub Pagesで公開後に実URLを再確認

**インテリジェンス**

- 「動く」だけでなく、誤操作、通信失敗、情報不足を前提に確認する。
- 予約住所など検証できない情報を完成扱いにしない。

## 9. 公開

**作業**

- 既存リポジトリの `app/seoul/` に追加する。
- 既存の回転寿司アプリは変更しない。
- GitHub Pagesの既存自動公開を使う。

**インテリジェンス**

- 新しい基盤を増やさず、以前動いた公開経路を再利用する。
- 旅行専用アプリを独立フォルダーにして、既存アプリへの影響を避ける。
